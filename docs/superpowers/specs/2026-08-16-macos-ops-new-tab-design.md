# macOS 运维新标签页设计规格

日期：2026-08-16  
状态：已实现并验收  
目标平台：当前 macOS 设备上的 Chrome

## 1. 目标

把 Chrome 新标签页替换为一个只读的个人运维首页，让用户在打开新标签页时完成两件事：

1. 快速进入常用网站。
2. 在几秒内判断本机 Docker、监听端口和远程服务器是否正常。

首版不提供容器启停、进程结束、远程命令执行或配置修改能力。

## 2. 设计原则

- 单屏优先：1440 × 900 下展示核心状态，不依赖首次滚动。
- 异常优先：红色和橙色只用于离线、采集失败和超过阈值的状态。
- 只读安全：所有运维信息仅展示；详情通过展开或跳转现有管理页面查看。
- 本机优先：本机状态刷新更快，远程状态通过哪吒监控读取。
- 最小实现：不引入账号系统、云同步、后台任务队列或自建监控数据库。

## 4. 页面模块

### 4.1 顶部状态栏

- 展示日期、时间、手动刷新和设置入口。
- 展示 Helper 连接状态及最近一次成功更新时间。
- Helper 断开时保持上一次数据，但明确标记为“数据已过期”。

### 4.2 搜索与快捷入口

- 搜索框提交普通文本到用户配置的搜索引擎；看起来像 URL 的内容直接打开。
- `⌘ K` 聚焦搜索框。
- 快捷入口展示图标与名称，支持新增、编辑、删除和拖动排序。
- 配置只保存在 `chrome.storage.local`，首版不做 Chrome Sync。

### 4.3 汇总卡片

- Docker：运行中与已停止容器数。
- Listening Ports：设置了关注端口时，展示关注总数、监听中数量和未监听数量；未设置时展示全部 TCP 监听端口数与 Docker 映射端口数。
- Servers：在线、离线服务器数与在线节点平均 CPU 使用率。
- Attention：当前异常总数，来源包括关注端口未监听、采集失败、服务器离线和资源超过阈值。

### 4.4 Docker 容器

- 默认展示运行中的容器，再展示已停止容器。
- 每行展示容器名称、状态、运行时长、发布端口、CPU 和内存占用。
- 首屏最多展示 5 条，“查看全部”打开只读抽屉。
- 点击行只展开镜像、容器 ID、端口映射和启动时间，不执行操作。

### 4.5 本机监听端口

- 展示 TCP LISTEN 端口；UDP 首版不展示。
- 设置中的“关注端口”为空时，展示全部 TCP LISTEN 端口。
- 配置了关注端口后，只展示关注端口，并为未被监听的端口保留一行“未监听”状态；不能只过滤 `lsof` 已返回的结果。
- 关注端口必须是去重后的 `1` 到 `65535` 整数列表，设置界面使用标签输入，不支持端口范围表达式。
- 每行展示端口、监听状态、进程名、PID 和来源。
- 来源尽量归类为 Docker/OrbStack、Homebrew、FlyEnv 或普通 macOS 进程；无法识别时显示“系统进程”。
- 未设置关注端口时支持“全部”和“Docker”过滤；设置后隐藏这两个过滤器，并显示“关注端口模式”和修改入口。
- 点击监听中的端口时，仅对常见 HTTP 开发端口显示“打开 localhost”链接；不自动请求端口，未监听端口不提供跳转。

### 4.6 服务器状态

- 展示在线状态、CPU、内存、磁盘、上下行速率和离线时长。
- 默认按异常优先、离线优先、名称排序。
- 点击卡片跳转到配置的哪吒 Dashboard 服务器详情页。
- 当前异常只根据最新快照计算，不在本地保存历史告警。

## 5. 视觉状态

- 正常：绿色状态点，其他文字保持中性色。
- 警告：橙色，用于资源超过警告阈值或数据开始过期。
- 严重：红色，用于关注端口未监听、服务器离线、采集失败或资源超过严重阈值。
- 未知：灰色，用于首次加载、字段缺失或哪吒未返回数据。

默认阈值：CPU、内存、磁盘达到 80% 为警告，达到 90% 为严重。阈值可在设置页分别调整。

## 6. 最小架构

```text
Chrome 新标签页
      │ HTTP 只读请求
      ▼
127.0.0.1 本地 Helper
      ├── Docker CLI / Docker socket：容器与资源状态
      ├── lsof：TCP LISTEN 端口与进程
      └── 哪吒 REST API：服务器列表与运行状态
```

Chrome 扩展不直接执行系统命令，也不保存哪吒 PAT。Helper 仅监听 `127.0.0.1`，对扩展提供固定的只读 JSON 接口。Helper 只接受目标扩展 Origin，并要求每次请求携带安装时生成的本机随机凭证，避免普通网页读取本机运维数据。

哪吒使用 REST API，不使用 MCP：看板需要的是服务器列表和状态读取，REST 路径更直接；MCP 的远程执行和文件能力不属于首版范围。PAT 只授予 `nezha:inventory:read`，并配置服务器 ID 白名单。

## 7. 数据流与刷新

1. 新标签页打开后立即读取本地缓存，避免白屏。
2. 页面请求 Helper 的聚合快照。
3. Helper 并行采集 Docker、端口和哪吒状态，返回各自独立的结果与时间戳。
4. 本机数据在页面可见时每 10 秒刷新一次；服务器数据每 30 秒刷新一次。
5. 页面隐藏后停止轮询，重新可见时立即刷新。
6. 手动刷新会立即执行一次完整采集，但不改变自动刷新周期。

某一数据源失败时，其他模块继续更新；页面保留失败模块的上一次成功数据。

## 8. 错误与空状态

- Helper 未安装：显示安装说明入口，快捷入口与搜索仍可使用。
- Helper 已安装但未运行：显示重连状态和启动说明，不循环弹窗。
- Docker/OrbStack 未运行：Docker 模块显示“Docker 未运行”，端口模块仍正常工作。
- 哪吒未配置：服务器模块显示配置入口，不影响本机模块。
- PAT 无效或权限不足：显示 401/403 的可读说明，不显示 Token 内容。
- 哪吒不可达：保留上一次成功数据并显示数据年龄。
- 无容器、无端口或无服务器：显示对应空状态，不把它当作错误；已配置的关注端口全部未监听时，逐项显示未监听，不使用空状态。

## 9. 设置范围

首版设置项只有：

- 页面标题与问候名称。
- 搜索引擎。
- 快捷入口。
- 关注端口列表；为空时显示全部 TCP 监听端口，设置后只显示关注端口及其监听状态。
- 哪吒 Dashboard 地址。
- 资源警告和严重阈值。
- 本机与服务器刷新间隔。

哪吒 PAT 由 Helper 的本地 `.env` 持有，文件权限设为仅当前用户可读写，不通过设置页回显，也不写入日志。

## 10. 验收标准

- 新标签页在 Helper 正常时展示真实 Docker、TCP LISTEN 端口和哪吒服务器状态。
- Docker 运行数、停止数与 `docker ps` / `docker ps -a` 一致。
- 端口、PID 和进程名与 `lsof` 的 TCP LISTEN 结果一致。
- 配置关注端口后，列表不再显示其他长期运行端口；未监听的关注端口仍然出现并计入 Attention。
- 哪吒在线状态和主要资源值与 Dashboard 当前状态一致。
- 任一数据源失败不会导致整页不可用。
- 页面和 Helper 均不存在容器控制、进程终止或远程执行入口。
- 哪吒 PAT 不出现在扩展代码、页面 DOM、日志或浏览器存储中。
- 普通网页无法调用 Helper 的只读接口。
- 页面隐藏时停止轮询，重新打开后恢复刷新。

## 11. 首版明确不做

- Docker 启停、重启、删除或日志查看。
- 结束端口占用进程。
- 哪吒 MCP、远程命令或文件管理。
- 历史趋势图、告警历史和本地数据库。
- 多设备同步、登录、团队共享和移动端适配。
- 自动发现并导入浏览器书签。
